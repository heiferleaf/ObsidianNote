# 学习笔记归档规则

仅管理学习内容。Pages inbox「临时笔记」用于用户自行创建、暂未分类的页面，由每周归纳整理。Router / Worker 创建的笔记，包括模板、用户提供正文和学习聊天总结，创建时直接放入合适的正式目录；最终分类对应本地 002-学习笔记。页面创建方式与正文来源分开记录，origin=manual 不代表页面由用户自行创建。日记、项目、电子书、根目录杂记不因整理被迁入；根 Agent.md 保留。

## 选择归档位置

1. 先读正文，判断学习语境，再确定主题和内容类型。已有课程的章节、作业、读书笔记保留课程上下文；独立概念、库/框架和系统机制归技术主题。面试问答优先面试准备；排查、实验按所解决的主题归档。
2. 优先最具体的既有目录。技术学习用于专题探索和实训（AI Agent、LLM、RAG 等）；技术栈用于可跨课程复用的工程知识；课程学习用于明确课程主线；面试准备用于问答和追问；零碎知识笔记用于已明确成文、尚无稳定专题的独立知识。
3. 通用知识、课程、阅读、实践实验、面试、问题排查是内容结构，不要求额外建六个顶层目录。阅读放到所属主题的读书笔记分支，实验和排查放相应主题/课程下；有足够内容再增子分支。
4. 多主题笔记选主要学习目标作为唯一归属，其他主题用标签和关联链接连接，不复制多个实体页。标题相似但课程、深度或目的不同的页可并存；内容重复需先比对、保留有价值差异，再做用户可理解的链接。
5. 对用户自行创建的临时页，内容不足、来源不明或两个目录都同样合理且上下文无法消解时，保留 inbox，报告简短原因。不要为清空 inbox 强制分类，也不要把所有临时页都扔进零碎知识笔记。Router / Worker 新建页的归属无法确定时，先澄清目录再创建。

## 真实移动与拓展

- 每周归档集合只取 inbox 中用户自行创建的直接子页。list_pages 按 next_cursor 分页，检查真实 parent，并根据 manifest 的 page_creator 与可核实创建记录判断创建方式；不按正文来源或账户 ID 猜测，未知项暂留说明。目录树可递归查阅，但后代不另列为本周归档对象。
- 先用 live 树验证目标存在、可写且属于同 Space。move_page 使用原 Page ID 与实际目标父 Page ID；核对完成回执或读回 parent。不能以复制正文、建新页、删原页代替移动。
- 下方树来自本次 plan.json 的 folders，仅作为目录意图；真实 Page ID 与父级以 manifest 和 live 结果为准，不能把目录字符串当作 ID。
- 当现有目录无法表达一个明确、可持续的主题时，在最相关父目录拓展。优先复用既有命名与层级；单篇长文不自动拆目录，确有独立专题时可建一个新分支，不设僵硬篇数门槛。
- 新分支先创建真实目录 Page，保留创建幂等键与收据，再登记 manifest 的 kind:folder、path、parent_page_id、url，同时更新本文件目录树及理由。不另开 Space，不自动改名整棵树。
- 页移动后的 path/parent 更新必须保留本地未同步改动；先检测基线冲突，再迁移本地路径并复查所有入链。只改变目录归属不构成重写学习正文的授权。
