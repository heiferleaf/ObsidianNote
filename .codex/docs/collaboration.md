# 学习知识库的多会话协作

Router 负责接收需求、选择 Worker 并检查结果。工程、图文格式和每周归纳分别由对应 Worker 负责；用户也可以直接在 Worker 中学习和返工。

## 创建和接续

新 Worker 创建前，Router 在 `.codex/docs/roles/` 写简短角色文档。首条消息指定负责领域、项目路径、角色文档、首次任务和交付要求；Worker 读取角色文档后开始工作。

后续沿用本聊天和 Codex 原生上下文压缩接续。较长或跨 Worker 的工作，按需把关键决定、已有结果、材料入口和下一步写进交接文档，在重要进展时更新。角色文档变更时，由 Router 发消息说明变更并要求相关 Worker 读取新版。

Router 根据创建工具回执，在 `.knowledge/threads.json` 记录真实聊天 ID、标题、领域和角色文档路径，供派工、查找和笔记关联使用。Worker 无需自行登记或执行身份查询；已有合适 Worker 就复用。根 Agent.md 是学习笔记。

## 短任务直接交接

Router 发清楚目标、材料入口、修改范围和预期结果。Worker 读取材料后执行，在本聊天返回产物、检查和未解决问题；Router 读回实际结果再交付。无需填写任务 JSON 或流转状态。

需要跨会话接续的工作，再写 `.codex/docs/handoffs/主题.md`，说明负责人、材料、已有结果、下一步和未解决问题。

## 共享材料放哪里

- `.codex/docs` 保存方法、接口、结论和交接材料，接收者读最新原文。
- Router 中转分工、依赖和分歧，长期决定再写入文档或 Page。
- 项目负责的 Page 保存正式学习内容。通过 state / manifest 定位真实页面，遵守页面编辑、公式源和双端同步规则，docs 只引用入口与必要摘要。

共享材料不会自动唤醒聊天，需要继续执行时由 Router 派发。同一内容明确一处正文来源，尽量串行修改同一文件或 Page。发送结果不明时先核实，避免重复派发。

现有每周自动化继续由归纳 Worker 执行。新笔记的来源与维护者按原业务表登记，已有笔记不补录索引。业务字段和历史技能路径保留兼容，不再增加第二套身份表。
