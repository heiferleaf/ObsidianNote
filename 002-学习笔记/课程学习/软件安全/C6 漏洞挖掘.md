# 漏洞挖掘技术分类

## 静态分析方法

**不需要运行程序**，分析程序潜在的漏洞。**分析效率高、资源开销小**。
代表方法：
- 符号执行
- 污点传播分析
- 词法分析
- 数据流分析

## 动态分析方法

**需要运行程序**，发现程序的漏洞。**查找准确率高、遗漏率低**。
代表方法：
- 动态符号执行
- 动态污点分析
- 模糊测试

# 符号执行

## 概念

**使用符号代替具体的变量，收集程序语义，探索程序可达路径，分析潜在漏洞**。
动态符号执行，在实际执行的同时，进行符号执行，在保证测试精度的前提下，提高执行效率。

## 步骤
1. **变量符号化**：把外部输入的数值转为符号，变量通过符号的表达式来表示
2. **模拟程序执行**
	1. 对于运算语句，把变量用符号表达式替换
	2. 对于分支语句，记录不同的路径和进入路径的约束条件
3. **约束求解**：对所有的路径，通过其约束条件进行求解，**判断路径是否可达，对可达路径生成测试输入**

> 符号分析在路径组合数量爆炸的情况下无法使用

# 污点分析

## 概念

**通过标记程序的外部输入数据或内部数据为污点，追踪程序流程中，污点数据的处理流程，完成对程序的分析**

污点分析分为**静态的污点传播分析**，和**动态的污点分析**。静态分析通过模拟程序运行，对污点传播进行分析，动态分析通过实际运行程序，传播并追踪污点数据。

污点分析常用来挖掘注入类的漏洞，如SQL注入、SOAP注入
## 步骤
1. 标记**污点源**
2. 确定**污点传播规则**：包括污点的扩散、清除。一般的计算、赋值语句是扩散；常值赋值是清除
3. 进行**污点检测**：在程序的敏感位置，对污点进行判定。常见的敏感位置包括**程序的跳转、函数调用**


> [!NOTE] 污点分析和符号执行的核心差异
> 泛化的来看，两者并无过多的差别，追踪变量的指令路径，和关键程序点是否会引发漏洞。
> 但是从规模、精确度方面，会有很多的差异
> 符号分析：针对符号的所有执行路径，分析约束条件，进行约束条件的求解，找到是否有漏洞的输入
> 污点分析：针对某一污点，只关注传播行为，扩散、清楚，最后到敏感程序触发被某一污点污染的警告

# 词法分析

## 概念

对代码进行基于文本或者字符标识的匹配，进行分析，查找符合**特定特点**和**词法规则**的**危险**函数、api、语句组合。

实现比较简单，执行效率高，但是会有很多的漏测和误报

# 数据流分析

## 概念

数据流分析是分析数据在程序执行路径中流动信息的技术，分析目的是**数据的流动路径和取值可能**。
按照分析路径的深度，分为过程内分析和过程间分析：
- **过程内分析**：针对函数中的代码进行分析，进一步细分
	- 流不敏感分析：按照代码行号从上到下分析
	- 流敏感分析：先产出程序**控制流程图（CFG）**，按照其拓扑排序分为
		- 前向分析：分析指定行号后续的代码段
		- 反向分析：分析指定行号前面的代码段
	- 路径敏感分析：考虑语句的先后顺序和语句的可达性。按照实际执行路径进行分析
- **过程间分析**：考虑数据在函数之间的传递
	- 上下文敏感分析：对不同位置调用同一个函数加以区分
	- 上下文不敏感分析：对不同位置调用同一个函数，传入不同参数，不加以区分

## 使用方式

1. 进行代码建模：将源码转为抽象语法树或者 CFG
2. 追踪变量变化信息

# 模糊测试

属于黑盒测试的一种，向程序输入大量**畸形数据**，并检测异常来发现存在的漏洞。

一般步骤：
1. **确认测试对象和测试数据**：根据目标程序，确定可能的输入数据
2. **生成模糊测试数据**：根据确定的输入数据，选用测试数据生成算法，生成畸形数据
3. **测试畸形数据**
4. **检测程序异常情况**
5. 确定可利用性：确定异常是否是可被利用的漏洞，不是必须的操作

模糊测试因为测试数据是基于合法数据畸变生成，无法保证不同情况的覆盖率。衍生出智能模糊测试（白盒测试），在通过符号分析、污点分析等程序分析手段之后，理解程序代码，针对的生成畸变测试数据。

# 程序切片

对于复杂大规模的代码，通过切片技术，快速提取收到一个变量影响的代码行（**前向分析**），或者影响变量的代码行（**后向分析**）。

切片的方法：
- CFG ： 每行代码是结点，组织结点的运行流程关系
- PDD （程序依赖图）
	- 将结点的边分为**数据依赖**（结点A影响结点B的数据，一定影响）和**控制依赖**（结点A的条件语句为真或假，会影响B的数据，不一定影响）
- SDD （系统依赖图）
	- 在 GDD 基础上补充函数调用结点

切片时，如果考虑特定输入情况，就是**动态切片**
# 程序插桩

在目标程序的代码文件中插入自定义代码，获取程序信息。
- 源代码插入：在源代码编译的时候，插入自定义代码。
- 静态二进制代码插入：在源代码编译好后的目标文件链接时插入自定义代码。
- 动态二进制代码插入：程序运行时，拦截其动态链接的代码，插入自定义代码

# Hook

> 插桩是修改代码文件，自定义功能。属于加工。
> 
> Hook 是拦截原本要执行的代码，改为执行自己的代码，**狸猫换太子**；或者是监听到消息，执行特定代码逻辑。

## 消息 Hook

消息分为单个进程的消息（线程钩子）和系统的消息（系统钩子）。
- 如果对同一个消息设置了线程钩子和系统钩子，**先触发线程钩子**。
- 一个消息的多个钩子链式执行
通过 createRemoteThread 可以先进程内存空间注入 DLL

## API Hook

API 被调用，Hook 将其修改为自定义函数。
- IAT Hook：修改 IAT 表中的函数地址
- 代码 Hook：将函数映射到内存空间时，直接修改物理内存中的代码
