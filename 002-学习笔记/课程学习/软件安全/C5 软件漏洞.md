# 软件漏洞

> 漏洞，也称脆弱性（Voluntarily）。指计算机系统的软件、硬件在系统设计、具体实现、系统配置、安全策略上存在缺陷，这些缺陷被利用之后，计算机的信息安全或者功能可能遭到破坏。
> **软件漏洞**：专门指计算机系统在软件层面的漏洞。

## 缓冲区溢出漏洞

   **缓冲区**：内存中一片连续区域，存放程序代码或者数据

   **缓冲区溢出**：向固定大小的缓冲区，写入超过其容量的数据，多余的数据会覆盖相邻的内存空间。
   
   一般攻击的内存对象是栈中函数返回地址、堆的块首管理结构、函数指针（SEH、虚函数表），让程序去执行其他代码。
   
   > 缓冲区溢出的本质原因，是没有对数据边界条件，或者函数指针引用进行边界检查。
   > 缓冲区溢出的种类：栈溢出、堆溢出、异常处理SEH结构溢出、单字节溢出

### 栈溢出

在函数中写入的数据长度，大于预留的栈基址ebp到esp之间的空间大小，覆盖栈帧中的返回地址。
在做栈溢出的实验的时候，需要注意栈中存放的多字节的数据，比如返回地址、局部变量（不是char类型）、栈基址值，在x86架构下，都是==小端法==存放。

> [!NOTE] 小端法
> 
> 假设我们有一个 32 位4字节的int变量 `int a = 0x12345678`。以字节为单位进行拆分，分别为 `0x12 0x34 0x56 0x78`
> 其中 `0x12` 是其中的高位，`0x78` 是其中的低位。在小端法中，栈中的存放的方式如下：
> 从低地址 - 》 高地址
> `0x78 0x56 0x34 0x12`

### 堆溢出

通过获取两个堆块 A B，（A地址 < B地址），向A中写入数据量大于 （&B - &A ）的数据，可以覆盖B的堆区内容。

不止于此，我们可以设置一个空闲块的块首信息，修改其中的 FD （下一个空闲块地址）和 BD（上一个空闲块地址）。
只需要设置 FD + 一段偏移量（BD在块首中的偏移量，对应 node->pre==->next==）为指定地址，把 BD内容设置为指定值，就可以向任意地址写入任意值。
这种攻击叫做 **Dword shoot** 攻击

> 堆块分配的时候，都会让 node->pre->next = node->next


### SEH溢出

^9eb896

异常处理结构体 SEH，是Windows提供的异常处理机制，对应的内核的实现，给高级语言的异常处理使用。

每一个 SEH 结构体包含两个 DWORD 指针，异常处理函数句柄 和 SEH 链表指针。
前者意如其名，后者是所有的异常处理方法串联的关键。

异常处理的串联：
- SEH 结构体是放在线程的栈区中的
- 当线程初始化，分配线程栈区的时候，就在栈中安装一个SEH，作为默认异常处理
- 当某一个函数代码，写了try catch代码段的时候，会在函数栈中安装 SEH 结构体，设置对应的函数处理句柄，和指向上一个 SEH 地址的指针
- 线程还持有一个 TEB（线程环境块），用来指向最顶端（也就是最深层的函数栈，因为栈向低生长）

SEH 攻击。就是通过覆盖 SEH 链表的入口地址，异常处理函数句柄或者链表指针，控制程序执行流程

## 格式化字符串漏洞

C / C++ 中，格式化输出的函数，匹配的都是可变参数
```c
printf(format_string, arg1, arg2,..., argn);
```

| 格式符   | 输出类型/含义               | 说明/示例（简要）                            |
| ----- | --------------------- | ------------------------------------ |
| `%d`  | 输出整型（int），十进制         | 例：`printf("%d", 10);` → `10`         |
| `%ld` | 输出长整型（long），十进制       | 例：`printf("%ld", 100000L);`          |
| `%o`  | 以八进制形式输出整数            | 例：`printf("%o", 10);` → `12`         |
| `%x`  | 以十六进制形式输出整数（小写）       | 例：`printf("%x", 31);` → `1f`         |
| `%u`  | 以十进制输出无符号整型（unsigned） | 例：`printf("%u", 10u);`               |
| `%c`  | 输出单个字符                | 例：`printf("%c", 'A');` → `A`         |
| `%s`  | 输出字符串（char*）          | 例：`printf("%s", "hi");` → `hi`       |
| `%f`  | 输出浮点数（小数形式）           | 例：`printf("%f", 3.14);` → `3.140000` |
> 这里说的整型，都是指32位
> 对于32位机，也没有64位的long或者longlong类型

在格式化输出的函数中，当传入的**可变参数数量**少于格式化字符串中**格式符**，对于剩余格式符的解读，会从栈中继续读取。因此，**会泄露栈的信息**

进一步，通过 %n 格式化，我们可以向任意地址写入想要的数据。

> [!NOTE]  %n
> 
> `printf("hello%n", &num);`
> 将输入的字符串的长度，写入到指定地址中。示例是把5（hello的长度）写到num变量的地址中，后续可以读取 num = 5。
> 
> char buf\[100];
> spinrf(buf, "想要注入的地址%【想要注入的数值十进制表示】%n");
> 会向地址处写入【中的长度数值】

## 虚函数攻击

C++ 中，虚函数（virtual）都是放在一个虚表中，每一个实例化对象，对象的内存空间头部的一段固定偏移量的字段，指向这个虚表，通过复写虚表地址，劫持程序流。

## 注入类型漏洞
（与其说是漏洞类型，更像是一种结果（代码、数据被注入到服务器运行），其原因可以是多样的，比如SEH攻击、栈缓冲区溢出、虚函数攻击
> 输入类型漏洞的特点：外部的数据输入被当作代码执行，或者非预期的指令被执行。从而影响到计算机的安全
> 注入类型的漏洞可以分为两大类：
> 1. **二进制**代码注入：将计算机可以执行的二进制代码，注入到其他应用程序的执行代码中，通过软件漏洞劫持程序流，执行注入的代码
> 2. **脚本注入**：注入脚本解释程序可以解释并且执行的数据。原因是因为程序没有对输入数据进行过滤

# 漏洞利用

>针对软件中已有的漏洞，针对漏洞的类型和特点采取相应的技术方案，进行尝试或者实质上的攻击。
> exploit（利用）


- shellcode：植入进程的代码，是一种漏洞利用的技术。
- 漏洞利用Expolit，包含了漏洞的触发，控制权限转移，shellcode执行的完整流程
- 能实现 Expolit 目标的有效载荷，叫做Payload。
> Expolit 利用漏洞的行为，shellcode 实际入侵进程的代码，Payload 包含 shellcode攻击代码、漏洞触发代码，程序流程转移的代码。
> 通过 Payload，最后执行 Payload 中的 shellcode，整个过程叫做 Expolit


shellcode 的编写，有一些注意点：
- ==一些特殊字符需要编码处理==：通过strcpy函数做缓冲区溢出的时候，碰到null会认为字符串读取结束，所以 shellcode 对一些特殊字符需要编码；在不同的平台上，字符集可能会有差异，所以也需要进行编码；此外，编码还可以绕过一些安全检测
- 函数的API定位麻烦，特别是系统调用的API，封装一层之后给用户使用的。所以要通过==动态方式获取api==

Shellcode 一般还需要进行编码处理，为了：
- **绕过坏字符**，比如上述说的 null 导致提前结束输入的读取
- 不同平台的编码字符集差异
- **绕过安全检测**

Shellcode 编码的方式
- 网页的 Shellcode ，可以用 Base64 编码，解码一般服务器支持
- 二进制的 Shellcode，可以通过PE加壳的思想 
	- 编码：异或编码 等方式
	- 解码：在shellcode执行开始的地方，进行解码


# 漏洞利用防护

因为缓冲区溢出，本质是因为高级语言没有对缓存区的写入进行边界检查，所以为了防范，操作系统采用了一些防范技术。下面都是 Windows 操作系统中常用的防范漏洞利用的技术。

1. **ASLR**：Address Space Layout Randomization 地址空间布局随机化。
   
	shellcode 的执行，往往依赖一些已有函数，比如系统调用，dll中的函数，通过可执行文件加载的时候，随机化一些地址，让 shellcode 失效。
	
	微软提供了两种方式实现随机化：
	1. **系统加载**地址的随机化：ASLR随机化的关键系统地址包括: PE文件(exe文件和dll文件)映像加载地址、堆栈基址、堆地址、PEB和TEB（Thread Environment Block，线程环境块）地址等
	2. **编译器选项**：编译器可选选项，开启后，编译的程序运行时，内部的栈结构等发生变化
	
2. **GS Stack protection**：栈缓冲区溢出保护，在返回地址和新栈帧缓冲区之间设置一个随机数（secure-cookie），函数返回值，检查随机数是否被修改
	
	和 CSAPP 中学习的金丝雀值一个内容。配合 ASLR 使用，随机数的存放位置随机化，防止手动恢复随机数值。
	
3. **数据执行保护 DEP** ：设置堆栈内存代码不可执行，防止溢出之后的代码执行
	- 分为软件 DEP 和硬件 DEP
	   
4. **SafeSEH**：
	1. 把所有的 异常处理函数 地址解析成一张异常处理表，表放在PE文件的数据块中
	2. PE 文件加载时，对上述的表进行随机数加密。*将加密后的SEH函数表地址、模块的基址、模块的大小、合法SEH函数的个数等信息，放入ntdll.dll的SEHIndex结构中*
	3. 在可执行文件运行时，如果需要进行异常处理，会先对表进行解密，然后检查
		- 要执行的函数是不是在表里，
		- 要执行的异常处理函数句柄是不是在栈中。
		溢出防止覆盖SEH和把shellcode放在栈中
	
5. SEHOP
	检查栈中 SEH 的完整性，包括
	- 链表组织的 SEH 结构体是否都在栈中
	- SEH 是否4字节对齐
	- SEH 异常处理函数句柄（函数地址）不在栈上
	- 最后的 SEH 结构体（线程初始化时安装的默认处理），其对应处理函数必须是 ntdll!FinalExceptionHandler 等函数

# 漏洞利用升级版

## 静态 Shellcode 地址的漏洞利用

如果存在缓冲区溢出漏洞的程序，是操作系统每次启动都要加载的程序，操作系统系统为其分配的内存地址一般固定，函数调用时的栈帧地址也固定。这种情况下，shellcode植入后栈区的地址不变，可以覆盖返回地址，指向这个静态的shellcode地址。

## 基于跳板指令的地址定位技术

- 有些漏洞存在于动态链接库中，程序运行时动态链接，每一次加载到内存中的地址变化
- 在使用 ASLR 技术的操作系统中，地址也会随机化
这种情况下，需要让覆盖后的返回地址，能指向正确的shellcode代码起始地址。通过一个跳板，间接实现。
1. payload组成：`[填充][指向 jmp esp 指令的地址（覆盖原本返回地址）][shellcode]`
2. 函数执行完 `mov esp ebp; pop ebp` 此时 esp 指向返回地址存放的低地址处
3. 函数执行 `ret --》 pop eip` 此时 esp 指向返回地址存放的高地址处，并且eip 指向的内容是 `jmp esp`
4. 随后 pc 正常 + 4 执行代码，但是代码已经是 shellcode。
> 总结，让esp在函数返回执行后，指向shellcode，绕开动态地址的问题。并通过 jmp esp 跳板指令，劫持程序流程


## 内存喷洒技术

在地址空间动态分布的前提下，通过堆区实现 shellcode 的执行。
Payload 构成：`滑板指令 nop; shellcode`
- 将 payload 大量注入到堆区
- 依赖于后续程序跳转到堆区中执行代码。会跳过滑板指令，执行 shellcode
> 总结，通过大量的shellcode在堆区中，绕开地址随机化（就像在地上导出喷洒液体，很难不踩到）
> nop 称为滑板指令，是因为cpu处理nop，直接pc+4


## API 自搜技术

ASLR 下，dll 加载到的地址随机化，导致shellcode在编写的时候，无法使用确定的系统调用或者库函数。
API 自搜索技术，就是通过代码编写，让shellcode的代码能自己定位到动态库函数中的地址。
- 通过段寄存器 `FS` 找到线程环境块 `TEB`
- 通过 `TEB` 找到 `PEB`（固定的偏移量）
- 通过 `PEB` 找到动态库链接链表（有三条，随便找一条）
- 找到动态库的导出表
- 从导出表定位函数名称->序号->地址表，得到 RVA，加上动态库的模块基地址，得到 VA
	名称匹配的时候，通过哈希运算后的结果匹配，速度块；不是直接字符串匹配

## 返回导向编程

为了突破 DEP 不让执行堆栈内存指令的限制而研发的技术。
通过漏洞覆写栈，让栈的结构
```
调用api
...
给 ebx 的参数
返回地址2（指向代码片段2） （pop ebx; ret）
给 eax 的参数
返回地址1（指向代码片段1） （pop eax; ret）
```
通过巧妙维护esp指向的地址，不断的准备参数，最后调用
- Windows 下的 **`VirtualProtect`** 或 `VirtualAlloc`
- Linux 下的 **`mprotect`**
把原本“只准写不准执行”的栈区的权限，在运行时硬生生修改为 **`PAGE_EXECUTE_READWRITE`（可读可写可执行）**

## 绕过 SAFE SEH 的防护

不是所有模块都会开启SAFE SEH，进行保护处理。通过覆盖那些的模块的异常处理函数句柄，进行攻击

# 实验三 利用栈溢出漏洞

软件代码如下：
```C
#define PASSWORD 1234567
int verify_password(char * password)
{
    int authenticated;
    char buffer[8];  //add local buff to be overflowed
    authenticated = strcmp(password, PASSWORD);
    strcpy(buffer, password);
    return authenticated;
}
```

在 `authenticated` 变量后，邻接一个缓冲区数组，并且最后写入数组没有对边界进行检查，所以可以通过设计 `password` 长度，覆盖 `authenticated` 的数值。

考虑到传入的字符串，末尾默认 `\0` 二进制 `0x00`。而 `strcmp` 后的结果如果是 0 或者是 1，在小端法的机器中，高地址--低地址 0x00 00 00 00/01，只要把最低的覆盖为 00。
> `strcmp(char * c1, char * c2)` 如果c1字典序小于c2，返回-1，对应0xffffffff。**所以password需要大于等于PASSWORD**

> password 的字节数量需要为8，加上默认的 \0，第九个字节就能覆盖 `authenticated` 的最低位的字节
