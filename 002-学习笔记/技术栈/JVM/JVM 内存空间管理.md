> JVM 是一个Java字节码的解释器，负责解释运行 JavaC 得到的字节码文件
> 了解 JVM 管理内存的结构，有助于明晰程序执行的逻辑


想要了解 JVM 内存管理结构，要先建立认知的角度
1. JVM Specialization ： 这是 JVM 的规范定义，从支撑 Java 程序运行时所需要这个角度，定义了 JVM 管理的内存区域
2. Hotpot JVM ： 这是一个具体的实现，其管理的内存区域，首先是给出了规范的具体实现，然后为了更好的执行 Java 程序，还定义了其他的区域
3. OS ：JVM 本质上就是操作系统正在运行的一个进程，虚拟内存空间的结构一定是符合 os 中学习过的划分方式的

# JVM Specialization 规定的 JVM Runtime Data

分两类，线程共享和线程私有的

1. **线程共享**
	1. Method Area
		1. 类的元信息
		2. 编译后的代码
		3. 静态变量
		4. 运行时常量池：类和其中方法的全限定名
	2. Java Heap
		1. 对象
		2. 数组
		3. 字符串常量池
	> 最新的 JDK 中，方法区在 Native Memory 中（本地内存这个概念见后）

2. **线程私有**
	1. PC 寄存器：不是内存中的区域，而是线程自己状态上下文的一部分
	2. 虚拟机栈：执行线程 Java 代码时的栈帧存储
		1. 返回地址
		2. 局部变量表
		3. 操作数栈
		4. 异常表：以前学习过的 [[002-学习笔记/课程学习/软件安全/C5 软件漏洞#^9eb896|SEH]] 较为类似，处理执行方法的异常
		5. 动态链接：在 Java 字节码加载到内存后，方法A内调用方法B，通过动态链接确定地址
	3. 本地方法栈：执行 native Method 使用的栈


# HotSpot 具体实现视角

**HotSpot Jvm** 是 JVM 规范的一种主流实现，对于规范中给出的 Method Area，具体的实现叫做 MetaSpace 元空间。

为了让 JVM 执行 Java 文件，除了实现上述的规范，还有别的内存区域，用于存放如
- GC 数据结构
- JVM 内部使用的数据结构
- Code Cache：JIT 编译的机器码
- **JNI**：Java Native Interface，Java 程序调用本地的方法，使用的接口。比如系统调用，C/C++ 写的库函数。通过 JNI 转为 C/CPP 方法执行

这些区域区分于 Java Heap，是为了让 JVM 运行时所需的其他资源的统称，叫做 native area/ native memory
- **抽象出的概念定义，不对应某一个内存区域**


# OS 视角下的内存管理

OS 视角下，只能看到正在运行 JVM 这个进程，进程本身管理堆区，可以申请在 mmap 区域中创建子线程。**和一般的进程无异**

但是对于 JVM 视角，它向 OS 申请内存区域，之后这区域就是自己管理的，在这个基础上，这个 JVM 进程为了可以执行 Java 代码，将这些区域做划分，堆区、虚拟机栈、本地方法栈等等。
