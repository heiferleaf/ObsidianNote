# 运行可执行文件，发生了什么

> 可执行文件，首先是磁盘上的文件，文件系统定位后，通过设备管理系统，读取文件到内存中，进程管理组织进程，配合内存管理分配内存给进程

1. **进程管理申请创建一个进程**
   - 创建 pcb：通过 `fork` 系统调用创建一个子进程
   - 分配 pid

2. **文件系统定位可执行文件**
 - 进程管理通知文件系统，要运行 `/path/file` 
 - 文件系统通过其组织的目录结构（操作系统加载时就在内核中），找到文件的 Inode 编号，进而读取元数据（大小、权限、数据块的位置）

3. **磁盘管理和内存管理的协作**
 - 进程管理调用 `execve` ，让内存管理创建进程的虚拟地址空间（动态链接+装入）
 - 可执行文件在磁盘上的内容不会马上全都读取，而是通过 `mmap` 把磁盘上的地址在虚拟页表中对应填写
 - CPU 想要执行第一条指令，发现缺页，触发缺页中断
 - 内存管理向磁盘管理发出请求，磁盘管理通过 DMA ，将内存的请求资源调入

4. 更新页表

5. 进程管理就绪
   - 进程的资源准备完毕，进入就绪队列，等待调度
   - 调度器选中进程，恢复上下文，执行进程程序

# 发生系统调用时，完成的处理流程

1. 执行的程序抛出异常（陷入），通过寄存器标识系统调用的类型和使用的参数（数量比较多，可以放到栈/内存块中，再把地址放到寄存器）
2. CPU 在时钟周期的末端检查收到的中断向量，从用户态进入到内核态
3. 硬件保护现场、关闭中断，根据中断向量和中断向量表，找到系统调用的入口
4. 执行软件保护，开启中断 （执行异常的时候，可以响应中断）
5. 根据寄存器参数找到对应的系统调用并执行
6. 关闭中断、恢复现场
7. 从内核态返回用户态


# 内存管理部分

## 为什么需要 TLB

TLB 快表用于加速内存访问，在局部性原理的指导下，说明一个页面被访问，其在最近时间内再次被访问的概率较大，通过把访问概率较大的表项，通过 TLB 组织。TLB 是 CPU 中的寄存器，访问速度比较快。访问页面一旦命中快表，就可以减少虚拟地址转为物理地址的时间。
- 局部性原理
- TLB 表访问快，价格贵，空间小
- 正常访问页表，需要两次访存，TLB 命中，访存只需一次

## 进程切换时，快表的行为

采用虚拟地址的进程，其地址会重叠，进而导致一个进程的虚拟地址，在 TLB 表的机制下，会访问到其他进程的物理内存空间，导致内存越界。

因而，根据 OS 是否支持 ASID（地址空间标识）/PCID（进程上下文标识），TLB 在进程调度时，对应的策略有：
- 不支持 ASID/PCID ：直接清空进程的快表项
	- 下次调度到进程，发生 TLB Miss，需要再次载入
- 支持 ASID/PCID ：在 TLB 中增加一个拓展字段，存放表项所属的进程
	- CPU 访问 TLB，除了需要匹配虚拟地址，还需要匹配进程标识

> 内核页面在 TLB 中的特殊处理，因为内核资源在所有的进程虚拟地址空间中都映射到相同的地址，本身就是所有进程共享的，所以不管是否支持 ASID，对于这些页面，在加载到 TLB 的时候，会标识为 Global，不会被清除。
